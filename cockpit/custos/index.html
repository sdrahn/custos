Model defaults for new agents

The model a new agent's configuration starts with, blank or from a template (/etc/custos/defaults.yaml, CONTRACT.md §14b). Each agent keeps the model in its own configuration: changing the defaults changes no existing agent. Secrets are not kept here: the credential is the name the key is stored under, such as model-key, never the key itself. Each agent gets its own key, stored encrypted (you are asked for it when you create one). A model server that needs no key needs no credential. Saving needs administrative access.

Create an agent

Its configuration (agent.yaml, CONTRACT.md §14), blank or from one of the shipped templates (§14a). agent-admin creates its user, units and schedules. A blank one starts supervised and with no permissions: it can do nothing until its tool boundaries list what it may do. One from a template gets the template's permissions and mode; its task categories stay supervised until you promote them. This needs administrative access.

Posture

What mcp-gateway enforces for each agent now: how many of its permissions run, wait for an approval, or run without one, and who may decide its approvals (the gateway's approver rules).

What would the gateway decide?

For one call of an agent: the gateway's policy decides it, with its reason, when Cockpit has administrative access; otherwise the page works it out from the agents' rules (agents.rego), without argument limits.
